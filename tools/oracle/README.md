# Oracle tooling

The pinned Java Closure Compiler (v20260415) is the specification. These tools
extract ground truth from it, layer by layer, for any JavaScript input, so the
Go port can be diffed against Java on arbitrarily large corpora instead of a
fixed set of hand-picked fixtures.

```sh
tools/oracle/fetch.sh    # .cache/closure-compiler.jar (sha256-checked) + .cache/closure-src/
tools/oracle/build.sh    # compiles java/*.java into .cache/oracle-build/
tools/oracle/corpus.sh   # pinned real-world corpus (corpus.txt) into .cache/corpus/
CP=.cache/closure-compiler.jar:.cache/oracle-build
```

| Tool | Layer | What it emits |
|---|---|---|
| `java/AstDump.java` | parser (`ParserRunner` → `IRFactory` → `rhino.Node`) | per file: parse diagnostics + the full `Node` tree, one node per line via `Node.toString(true, true, false)`, plus `JSDocInfo.toStringVerbose()` for nodes that carry JSDoc. `java -cp $CP AstDump <outdir> <root> <rel-file>...` |
| `java/ParsingDump.java` | parsing (`ParserRunner.parse`: Parser → IRFactory → `rhino.Node`, JsDocInfoParser) | per file: the `parsing.Config` the compiler uses, every message reported to the rhino `ErrorReporter` (with line/offset), the `FeatureSet`, source map URL, comments, and the `Node` tree (`Node.toString(true, true, false)` per node + `JSDocInfo.toStringVerbose()`), every line escaped to printable ASCII. A closure-unaware shadow host is followed by its shadow AST. This is the exact boundary of `internal/parsing`. `java -Xss1g -cp $CP ParsingDump [--gzip] [--lang=..] [--jsdoc] [--jsdoc-mode=<JsDocParsing>] [--keep-going] <outdir> <root> <rel-file>...\|@<listfile>`; the Go side is `internal/parsing/parsingdump_test.go` (`PARSE_ROOT`, `PARSE_ORACLE_DIR`, `PARSE_FILES`, `PARSE_DIFF_DIR`; it masks only the identity hash that `JSDocInfo.Marker` prints). |
| `java/JsDocDump.java` | parsing (`JsDocInfoParser`, driven the way `IRFactory` drives it) | per file: the `parsing.Config`, then for every JSDoc / important comment the parser collects: the diagnostics sent to the rhino `ErrorReporter`, `JSDocInfo.toStringVerbose()` and every marker, the license text and the file-overview state (plus `parseInlineTypeDoc` for comments without `@`), and finally the file-level JSDoc. In package `com.google.javascript.jscomp.parsing` (it calls package-private entry points): `java -Xss1g -cp $CP com.google.javascript.jscomp.parsing.JsDocDump [--gzip] [--lang=..] [--jsdoc[=<JsDocParsing>]] <outdir> <root> <rel-file>...\|@<listfile>`; the Go side is `internal/parsing/jsdocdump_test.go` (`JSDOC_CORPUS`, `JSDOC_ORACLE_DIR`, `JSDOC_FILES`, `JSDOC_DIFF_DIR`; goldens in `internal/parsing/testdata/jsdoc/`). |
| `java/FeatureCollectorDump.java` | parsing (`FeatureCollector`) | per file: `FeatureCollector.allFeatures()` after `visitScript` over the `ParserRunner.parse` AST (compiler config), one TSV line. `java -Xss1g -cp $CP FeatureCollectorDump <root> <rel-file>...\|@<listfile>`; the Go side is `internal/parsing/feature_collector_test.go` (`FEATURES_ROOT`, `FEATURES_TSV`). |
| `java/CliBatch.java` | whole compiler (CLI) | the exact `java -jar closure-compiler.jar ...` output and exit code, for many invocations in one JVM. Jobs on stdin: `<outfile>\t<arg>\t<arg>...`. Byte-identical to the per-process oracles in `testdata/oracle/`. |
| `java/ParseTreeDump.java` | parser (`parsing.parser.Parser`, before IRFactory) | per file: the parser config, every parse error/warning with its position, the feature set, the source map URL, the comment list and the whole `ProgramTree`, dumped field by field by reflection. Configured exactly as `ParserRunner.parse` does for `--language_in=ECMASCRIPT_NEXT`. `java -cp $CP ParseTreeDump [--gzip] [--lang=<LanguageMode>] <outdir> <root> <rel-file>...\|@<listfile>`; the Go side is `internal/parser/parsetreedump_test.go` (`PTREE_CORPUS`, `PTREE_ORACLE_DIR`, `PTREE_FILES`, `PTREE_DIFF_DIR`). |
| `java/RegExpDump.java` | regex (`jscomp.regex.RegExpTree`) | `extract <root> @<list>`: every distinct REGEXP literal (pattern, flags) in the files, collected from the `ParserRunner` AST (or, for files that do not parse, from `parser.Parser`'s regular expression tokens). `dump <patterns>`: per pattern, `RegExpTree.parseRegExp` → exception class + message, or `toString()`, `appendSourceCode`, the analyses (`numCapturingGroups`, `isCaseSensitive`, `containsAnchor`, `matchesWholeInput`, `hashCode`) and the node tree with `appendDebugInfo`, then the same for `simplify(flags)` (and `simplify(flags+"i")`). The Go side of each oracle (e.g. the Go `rhino.Node` dump) must reproduce the
Java format byte for byte; it is produced by ported code (`Node.toString`,
`JSDocInfo.toStringVerbose`), not by a Go re-implementation.

Generating the AST oracle for the whole corpus (two JVMs, ~5 minutes, 1.4 GB):

```sh
(cd .cache/corpus && find . -type f | sed 's|^./||' | sort) > .cache/corpus-files.txt
xargs -a .cache/corpus-files.txt -d '\n' java -Xmx3g -Xss16m -cp $CP AstDump .cache/oracle/ast/corpus .cache/corpus
```

Note for Go-side dumpers: Java's `PrintStream` encodes a lone surrogate as `?`,
so WTF-8 strings must be written with lone surrogates replaced by `?`.
