# Identity/hash/equality source audit

No production change or measurement is proposed as a proven win. Existing profile evidence predates the newest representation screens, and CPU ancestry truncates at64 frames; retained ancestry is not a hard whole-program ceiling.

The structural labeled capture retains typed inferTypes ObjectsEquals ancestry0.04s and checkTypes0.06s; bundle FSIV retains ObjectsEqualsOf pointer-key flat0.01s. Generic LinkedHashMap.find percentages mainly include direct Go string/pointer lookup and tiny-list traversal, not arbitrary Java hash dispatch. ObjectHashCode's previously observed0.9–1.7% flat share does not justify replacing every collection. These are limited samples, not predicted savings.

*Var and *TypedVar are structural keys: AbstractVarBase.Equals compares immutable name and scope-root, and HashCode combines their hashes. Equal distinct declarations with the same name/root must still match. The cached name hash and direct pointer-root hash already remove repeated name hashing and identity reflection. A raw map[*Var] replacement changes the public object-map semantics unless privately owned construction proves unique representatives; several such private native maps already exist, so that is not a new blanket optimization.

*Node/*Scope/*TypedScope have default identity equality, but LinkedHashMap already uses direct == and native Go hashing for comparable keys. Only ObjectLinkedHashMap or HAMT call sites pay the generic dispatch. JSType keys can have structural or mutable proxy semantics; pointer inequality cannot establish inequality. The previously tested outer flow-scope/CFG/native-reference paths must not be duplicated under a new name.

One bounded new candidate after measuring hit frequency is a concrete Var.Equals / TypedVar.Equals same-object fast path, restricted to initialized exact stock values and pure concrete Scope/TypedScope root access. Return true only for a nonnil identical concrete pointer with a valid nonnil scope/root; otherwise call the original AbstractVarBase.Equals. This preserves equal distinct Vars, cross ScopedName/TypedVar equality, malformed/public fallback and custom callback behavior. It avoids the second ScopedName interface conversion, nil reflection and virtual getters on canonical hits without changing collection layout, hash values, iteration, live views or persistent structure. Concrete HashCode overrides could additionally remove scope-root generic dictionary dispatch, but existing name/root caching limits the available work. No implementation is authorized by this evidence alone.

A generic jutil pointer-identity shortcut was considered and deferred. Java Objects.equals has a reference shortcut, but changing the existing port's generic callback invocation behavior would affect custom Equaler values. jutil cannot import jscomp/rhino without a cycle, and adding per-map function/mode fields would increase the many empty/tiny-map allocations. Avoid a broad new callback or reflection-name-based production dispatch merely to recognize stock keys.

Untimed source observation is prepared at identity-equality-overlay/overlay.json, generated by prepare_identity_equality_overlay.py from a clean frozen source tree. The manifest records source and overlay hashes. It counts exact concrete Var/TypedVar/Scope/TypedScope/Node operands at ObjectsEqualsOf, ObjectsEquals, ObjectHashCodeOf and ObjectHashCode, preserving all original calls. Same nonnil pointer, distinct pointers, nil cases and different dynamic types are separate. Of fallback calls also appear at dynamic sites: never sum those counts. Exact type names establish diagnostic classification, not valid constructor ownership.

The diagnostic binary adds atomics, reflection and interface conversions. Build/capture only under a coordinator slot, bytegate first, write JSGO_IDENTITY_KEY_AUDIT_OUT, and interpret counts only. Never use its elapsed/RSS/allocations or profiles as production performance evidence or PGO training. No build/test/capture has run for this audit.
