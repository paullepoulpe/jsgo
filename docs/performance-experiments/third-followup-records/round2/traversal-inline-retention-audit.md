# Obsolete traversal inline-stack retention

Source reviewed: compact4 9044aff9. No production/source/test changes made during the first macro/race validation.

Both PushScope and PushScopeOfScopeWithQuietly append directly into t.scopes. First overflow copies inline entries to a new backing array. Later PopScopeWithQuietly clears the current final entry and shrinks only that new backing; the embedded scopesBuf still contains its original entries. This is real for both the16 control and4/8 alternatives, not a new append algorithm.

For materialized entries the duplicate references retain Scope graphs, their parents, Vars, declaration maps and node metadata until traversal collection. For unmaterialized entries the duplicate retains only AST roots. Typical completed traversal already keeps compiler, callback, scopeCreator, currentNode and enclosing-function/hoist/script pointers; compiler or currentNode usually already retain the AST. The extra unique retention is therefore predominantly reconstructed scope/declaration state, unless the AST was detached or the traversal was manually driven. Default SyntacticScopeCreator itself stores compiler/handler configuration, not all created scopes. Typed or explicitly memoized creators can independently own scopes.

Compact4 adds this retention opportunity for max-live depths5..16, where control16 remains inline and clears all entries on pop. Its stale duplicate is bounded to4 scope entries versus16 after control overflow; total retained graph bytes are unbounded by that pointer count because one outer scope can own many declarations. No histogram or RSS claim is available yet. Most high-count FSIV per-CFG-node traversals do not query/materialize lexical scopes; the impact requires actual depth/materialization evidence.

Immediate one-time clearing after first successful growth is the correct high-level cleanup, with no extra fields/pools and no changes to current heap entries. However GetAbstractScopeAt currently holds a pointer to an entry across recursive parent materialization and custom ScopeCreator callbacks. A balanced reentrant creator may temporarily push/pop and trigger growth while outer frames retain those old inline entry pointers; immediate clear would erase their node field. A safe implementation must retain each queried node in a local value before recursing/calling a creator, then clear obsolete inline slots after append succeeds. Balanced callback stack restoration preserves exact logical entries; adversarial permanent replacement of queried stack slots already has original capacity-dependent behavior and must not be silently claimed newly supported.

A meaningful proposed regression test uses manually supplied scopes/AST unowned by compiler, a separate currentNode, stateless callback/scope creator, and retains NodeTraversal while holding only a weak reference to a popped Scope. This isolates inline backing as the only remaining scope owner, rather than merely observing an AST still retained by compiler/currentNode. A separate balanced custom creator should force first growth during recursive GetAbstractScopeAt and verify original node/parent/scope identities remain exact. Both Push variants and no-growth behavior need coverage. No standalone sizeof test would establish lifetime correctness.
