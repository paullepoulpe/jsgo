Do not extend this finding to candidates with different guards. Scope declaration recipes use a fresh CLI lease plus normalized-stage/observer checks, without this nil-table fence. Native reference storage selects its own structural name/root representation directly. Generic inline BitSet changes are unconditional. Fresh template values and access-control property facts operate before colors, where the nil-table check serves a different input-origin boundary. Existing native CFG/local flow/reference flags must be assessed individually, not declared inactive from these post-colorization findings.

The strongest old negatives to revisit, after proof and actual-CLI dispatch counters:

1. RUC task/list/FIFO storage. The recorded source audit targets a pass owning about 10.3% of an older bundle CPU profile, with many short-lived continuation/list objects. The complete pass share is not predicted savings, but this is a substantive storage target whose off/on timing may have compared two original backends.
2. Native liveness and its independent publication/scratch variants. They eliminate per-transfer lattice/BitSet allocation and repeated gen/kill work. Historical rounds 8/9/10 cannot support an enabled-solver effect on the three optimization tasks until real DoRun activation is demonstrated. Generic BitSet effects remain distinguishable and valid as unconditional binary changes.
3. Compact contextual rename storage. Its older bundle evidence attributes 313.56 MiB sampled allocation and 0.76/21.18 s sampled CPU to the complete pass; current scope/name/ownership semantics still require the existing exact differential tests. This is bounded evidence from an older source, not a current hard ceiling.
4. First declaration coallocation. It is byte-neutral and removes two objects for each eligible nonempty private scope; likely smaller than eliminating entire walks, but old off/on results did not test that work after colors.
5. ASCII output on optimized tasks. Whitespace's existing output path may have been active and its measurements should not be invalidated. Current source proof shows that private output/known license trackers never touch the runtime-library supplier table: Compiler_GetLicenseForFile calls GetScriptNode, which reads scriptNodeByFilename directly. Isolated fix24f79494 removes only that fence; validation/probe commit c1961e28 requires real WHITESPACE/SIMPLE/ADVANCED DoRun printer/join activation, UTF-8/source-map parity, and a throwing supplier table that must remain uninvoked.

Reporting implications: do not reinterpret old apparent gains as enabled feature wins, or old neutral/regressive samples as evidence that these algorithms failed. Preserve raw values and historical source IDs, annotate the admission gap, and run a new correctness/activation gate before any retiming. Public/custom/typed/saved-state fallbacks remain required. A phase-specific ownership proof is necessary; globally deleting every runtime-library guard would be unjustified.
