Interpretation clarification after the source-position screen; no protocol, threshold, raw counter, PASS status or statistical result changes.

`CompilationMXBean.getTotalCompilationTime()` reports approximate accumulated **elapsed compilation time** in milliseconds. When compilation uses multiple threads, their approximate elapsed times are summed. It is not compiler-thread CPU time or a CPU utilization percentage. See the [Java 21 API contract](https://docs.oracle.com/en/java/javase/21/docs/api/java.management/java/lang/management/CompilationMXBean.html#getTotalCompilationTime()). The historical `JIT / wall` field divides its counter delta by request elapsed time; keep the field and flags as declared, but interpret them as a compilation-elapsed-time proxy. This clarifies earlier loose descriptions of “compiler work.”

The local driver reads this bean in `bench/CliFactors.java` and samples it around each compiler request. The runner's `JVM.request` in `bench/run-v3.py` unpauses the selected container before its request and pauses it after RESULT. A compilation may begin before a pause and finish after resumption. If its elapsed timer spans that pause and the counter is updated later, paused duration can enter a subsequent delta although the compiler thread used no CPU while paused. Summation across threads and delayed updates also prevent identifying a counter delta with work entirely inside the request's wall-time window.

In the completed source-position screen, CONTROL's fifth measured delta was 8,554 ms, and its five-request ratio was 42.7717%; the candidate's ratio was 1.8556%. Treat the large ratio as a potentially contaminated compilation-elapsed-time diagnostic, **not evidence that JIT used 42.7717% of request CPU or caused a specific slowdown**. The rows do not identify which compilation spanned a pause or explain this jump. Matching HotSpot timer/accounting implementation source was not available locally (`src.zip` absent), so no implementation-level attribution is claimed.

All ordered counters, original admission outcomes and ratios remain. The single cohort does not establish a settled speed gain, and lower allocation/RSS observations remain descriptive.
