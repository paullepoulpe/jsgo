The accumulator is a reasonable allocation-focused refactor to submit for upstream evaluation. The BigQuery evidence below supports reporting a lower allocation total in that screen; it does not establish a repeatable general benefit or a speed improvement. A later independent bundle screen observed 3.8479% lower median elapsed, but only 1.6637% lower mean elapsed, with 6.7612% lower allocation and 5.2152% higher approximate lifetime HWM. It was selected for the sole v4 direct-STOCK bundle holdout; no holdout result is included here. Both screens remain separate, descriptive evidence.

Suggested report wording:

> Sharing one result set through `findModifiedParameters` recursion removes per-node scratch sets and intermediate merges. In one same-family CONTROL screen, the candidate's median VM-wide allocated bytes per compilation were 2,021,800,312 versus 2,079,177,752: 57,377,440 fewer bytes, or 2.7596% lower. All outputs matched on 54 paired warmups and five measured pairs. Elapsed median was 1.7791% higher, CPU median was unchanged, and current RSS median was 10.6425% higher. We retain the patch as an allocation-focused proposal; this screen does not establish a speed gain or lower retained memory.

The source change provides a mechanism for the observation: one invocation-local LinkedHashSet receives the same recursive additions in the same order, followed by the existing immutable result copy. It adds no cross-request cache. Source review, focused probes and workload byte parity cover their documented cases; the full upstream test suite has not run.

Keep the scope visible. The comparison is against rebuilt same-family CONTROL, not a direct published-STOCK confirmation. Five requests in one JVM pair are not five independent cohort effects. The observed allocation ratio is descriptive and has no independent-cohort confidence interval. These totals are VM-wide ThreadMXBean deltas, not JFR sample weights, object counts, live heap, or per-method allocation measurements. JIT fractions were 1.9463% and 1.7826%; being below the historical 2% annotation threshold does not prove complete settling. Approximate lifetime HWM was 1.1947% lower while current RSS was higher, so neither memory window should be generalized to a guaranteed footprint reduction.

Recommend review of the small patch and its allocation mechanism, while retaining “none promoted” for a confirmed performance result. Avoid “2.76% faster,” “lower memory use,” “no slowdown,” or “confirmed allocation win.” The observed slower elapsed median also does not establish a repeatable slowdown from one cohort; it must remain alongside the favorable allocation observation.
