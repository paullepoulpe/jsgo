# Native storage admission after type-to-color conversion

Source-only correction against c7998d45. This changes admission, not either storage algorithm, public constructor or feature flag. It has not yet been built, tested or measured.

Ordinary optimized source compilations run ConvertTypesToColors before normalization and optimization. That pass unconditionally initializes Compiler.runtimeLibraryTypedAsts: a table of deferred built-in library suppliers. The previous scope-first and compact-inverter guards rejected every nonnil table, so negative optimized-CLI screens did not test these representations. Transpile-only paths differ and cannot be classified from this finding alone.

Scope-first allocation constructs a fresh first Var, map and ordered entry during the original SyntacticScopeCreator declaration scan. NewVar initialization, canonical scope/Var identity, declaration order and legality/publication checks remain unchanged. Neither this constructor nor the stock IV/RUC scope scanner calls a runtime-library supplier. A loaded supplier table does not modify declaration-map ownership or coallocation retention: the map already retains its declared Vars, records are never reused, and public/custom creators keep the original allocation. RUC's extra synthesized declaration only appends. Original callbacks, custom redeclaration handlers, injected typed AST files, warning/reporting changes, and source ownership still have separate guards.

Compact inversion records exact final implementation VariableInfo identities, original shadow insertion order and current GetName observations. It performs the same syntax/name rewrite traversal and change reporting. It does not inspect colors, JSType objects or the runtime-library table, nor inject any runtime library. Table presence therefore cannot introduce a new callback or invalidate its invocation-local identity/lifetime proof. All typedAstFilesystem, custom warning/convention/observer/reporter and fresh-source ownership guards remain unchanged. Capacity retirement and traversal-failure cleanup remain the original implementation.

The flags remain independent: JSGO_EXPERIMENT_SCOPE_FIRST_ALLOCATION and JSGO_EXPERIMENT_COMPACT_INVERTER. Both still require the existing private stock factory and genuine JSGO_EXPERIMENT_CLI_SOURCE_LOCK lifecycle. This is not a general weakening of scopeFirstAllocationEligible for unrelated analyses; its only production caller in this base is the first-coallocation switch.

Coverage adds complete stock CLI Compiler.Compile lifecycles at N=1/2, installing only an existing private numeric probe on the exact pass returned by its original DefaultPassConfig factory. The tests assert a nonnil runtime table at the original RUC/inverter ordinal and positive actual first coallocations/compact shadow records, then compare output, diagnostics and change order with independent flag-off controls. Scope-first also covers stock insertion off/on. An unused throwing supplier proves non-use. Existing public/custom fallback and partial-failure cleanup tests now run with a loaded table; injected typed files and custom warning guards must still fall back. No test fabricates source-ownership markers in the complete CLI lifecycle test.

The CLI lifecycle tests call the stock runner's option creation, real source-ownership acquisition, Compiler.Compile and ownership release directly so they can attach the optional per-pass counters without production hooks. Existing DoRun artifact parity tests remain in their original suites. Untimed benchmark activation counters are still required before any new time/RSS interpretation. No gain is claimed by this correction.
